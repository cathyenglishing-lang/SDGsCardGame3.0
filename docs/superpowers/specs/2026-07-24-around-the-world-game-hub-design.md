# Around the World in 80 Conversations — Game Hub Integration

## Goal

Integrate the standalone `mono_game/around-the-world-in-80-conversations.html` (a Monopoly-style intercultural-communication board game, CEFR B1–B2) into the CardLearn SDGs Game Library (`frontend/pages/member_index.html`), using the existing `GAMES` array extension point that was already designed for this purpose (see `member_index.html` comment: "To add a Claude-built mini-game later: push a new object with status:'live', action:'link', url:'/pages/your_game.html'").

## Scope

- New standalone page: `frontend/pages/around_the_world.html`.
- One new entry in the `GAMES` array in `frontend/pages/member_index.html`.
- No backend changes. No database schema. No new API routes.
- No changes to `dist/` (regenerated by `npm run build`).

## Non-goals

- No score/session persistence to the backend. The game keeps its existing pure-client-side state (players, CP, board position, passport stamps) exactly as authored in the source file — no `game_sessions` / `game_part_records` rows are created for it.
- No rewriting of the 80-card content, board layout, or game logic. Content is copied as-is from `mono_game/around-the-world-in-80-conversations.html`.

## Design

### 1. New page: `frontend/pages/around_the_world.html`

The source file in `mono_game/` is an HTML fragment (starts directly with `<meta>` tags, no `<!DOCTYPE html>`/`<html>`/`<body>` wrapper). The new page wraps that fragment in the same document structure used by other game pages (`game_s.html`):

- `<!DOCTYPE html>`, `<html lang="en">` (game content is English-only), `<head>` containing the original `<meta>`, `<title>`, Google Fonts links, and `<style>` block unchanged.
- `<body>` containing the original markup (`#setup`, `#game`, modals) unchanged.
- Before `</body>`, add:
  - `<script src="/static/config.js"></script>`
  - `<script src="/static/js/api.js"></script>`
  - A guard script: `auth.requireLogin();` — run before the game's own inline `<script>` block, matching the pattern in `game_s.html` (`const user = auth.requireLogin()?.user;`). This just enforces that a logged-in session exists; the returned user is not otherwise used by the game.
  - The original inline `<script>` block (CARDS data + game engine) unchanged, appended after the guard.
- Add a small back-navigation control near the top of `#setup` and/or `#game` topbar: a plain link/button "← Back to Game Hub" pointing to `/pages/member_index.html`, styled minimally to match the page's existing ticket/topbar aesthetic (dark ink button, not a full redesign).

No other modification to the game's HTML/CSS/JS — board layout, card content, scoring rules, and UI stay exactly as designed in the framework doc (`mono_game/around-the-world-in-80-conversations-monopoly-framework.md`).

### 2. Game Hub entry: `frontend/pages/member_index.html`

Add one object to the `GAMES` array, placed after the existing `sdg-pecha-kucha` (live) entry and before the three `soon` placeholder entries:

```js
{
  id: "around-the-world",
  title: "Around the World in 80 Conversations",
  sub: "跨文化溝通 · 桌遊",
  desc: "Travel a Monopoly-style board through 10 intercultural zones. Draw a card, speak your answer in English, and earn Connection Points.",
  icon: "🌍",
  accent: "#2C5F9E",
  status: "live",
  action: "link",
  url: "/pages/around_the_world.html",
  tags: ["CEFR B1–B2", "Speaking", "Culture"]
}
```

This uses the existing `launchGame()` dispatch (`action === "link"` → `window.location.href = game.url`), so no changes to hub JS logic are needed — only data.

## Testing / verification

- `python -m py_compile backend/main.py backend/rate_limit.py scripts/test_rate_limits.py` — unaffected, run to confirm backend untouched.
- `npm run build` — confirms the new page copies into `dist/` and `dist/static/` correctly.
- Manual check: log in, open Game Library, confirm the new card renders and is clickable (`status:'live'`), click through to `/pages/around_the_world.html`, confirm the board/game loads and "Back to Game Hub" returns to `member_index.html`.
- Manual check: visiting `/pages/around_the_world.html` directly while logged out redirects to login (via `auth.requireLogin()`), consistent with other game pages.
