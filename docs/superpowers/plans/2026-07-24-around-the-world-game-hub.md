# Around the World in 80 Conversations — Game Hub Integration Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add the standalone `mono_game/around-the-world-in-80-conversations.html` board game as a new, logged-in-only page in the app, and expose it as a playable card in the `member_index.html` Game Library.

**Architecture:** Wrap the existing self-contained game markup (unchanged CSS/JS/card data) in the same document shell other game pages use (`config.js` + `api.js` + `auth.requireLogin()` guard), save it as `frontend/pages/around_the_world.html`, then register one new entry in the `GAMES` catalog array in `member_index.html` pointing at it via the existing `action:"link"` dispatch path.

**Tech Stack:** Static HTML/CSS/vanilla JS (no build step beyond the existing `npm run build` copy script), existing `frontend/js/api.js` auth helper.

## Global Constraints

- No backend changes, no new API routes, no database schema changes (per spec `docs/superpowers/specs/2026-07-24-around-the-world-game-hub-design.md`, Non-goals).
- Game content (80 cards, board layout, scoring, CSS) must be copied byte-for-byte unchanged from `mono_game/around-the-world-in-80-conversations.html` — no rewrites.
- New page must require login the same way `game_s.html` does (`auth.requireLogin()`), and must include `/static/config.js` + `/static/js/api.js` before any other script that needs `auth`.
- Do not hand-edit `dist/` — it is generated by `npm run build`.
